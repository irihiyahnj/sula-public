boot 权重体检的后续动作，体检本身在 2026-07-25 就做完了，没有下一步。

当前 103 条在force判断里 60 条早于 vector 迁移，讲的是 SQLite kernel cache、orchestration CLI、fleet executor、provider/Google Drive 集成、site bootstrap、0.18.x 各次发布——这些代码 2026-07-25 已整体移入 legacy/。它们仍然「在force」只因为没人取代过。

这是 B6 的实质失效：两步 boot 号称给出完整上下文，实际 58% 描述一个已归档的系统，而新 agent 无法从 boot 本身分辨哪些是活的。本轮我之所以分辨得出，是因为额外读了 README 和 legacy/ 的目录形状——那已经是第三步。

退休判定用机械口径而非日期直觉：tags 含 migrated-from-sula 的在force判断，60 条，与「早于 2026-05-23 迁移」的集合完全相等（已核对）。它们都是 legacy 运行时的 change-record，是实现日志，不是仍在生效的政策。

decision-legacy-0-18-x-legacy 说「仓库形状与论点一致」，但只搬了代码，没退休关于代码的判断。这条片段补上另一半。

- add-project-language-policy-for-generated-docs：讲的是 legacy manifest 的 [language] 段，该结构已不存在；但其中的语言政策实际仍在执行，另起一条 vector 期片段重述，不让活政策随实现一起蒸发
- sula-karpathy-inspired-agent-quality-policy：讲的是 legacy manifest 的 [agent_behavior] 段与 orchestration 闭环记录，两者都已不存在
