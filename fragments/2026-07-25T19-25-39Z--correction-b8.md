decision-b8 定的口径按时刻算：witness 的时间晚于最后一条深思片段即算缺口。这个口径错了,而且错得系统。

协议的正常顺序是：agent 改文件 → 写下判断 → 回合结束 → 钩子(Kiro agentStop 或 git post-commit)才运行 witness。于是 witness 的时间**必然**晚于那条解释它的判断,每一个守规矩的回合都会在下一次 boot 里被标为「Unexplained change」。一个总在喊狼来了的提示会被忽略,然后真的缺口也一起看不见——这比没有提示更糟。

我没在真实环境里撞到它,纯属侥幸：我这几轮都是手动先跑 witness 再写判断,钩子后来跑时无变更可捕,于是沉默。今晚提交那次也因为树已被捕获而侥幸躲过。这正是「测试与缺陷共享同一信念」的又一例——我的使用习惯恰好绕开了自己的规则。

改为窗口制：判定单位是**两次捕获之间的窗口**,而不是时刻。一个记录了变更的 witness,若自上一次捕获以来没有任何 judgment 或 direction 被写下,才算缺口。与顺序无关,判断写在前或写在后都算解释。有钩子时一个回合最多一次捕获,所以窗口≈一个回合,粒度正确。

保留不变：只有 evidence 不能销缺口(verification-fact 也不行);baseline 与无变更 witness 不计;永不进 doctor 退出码。同时删掉那条编码了旧口径的测试——它与钩子顺序的测试直接矛盾。
