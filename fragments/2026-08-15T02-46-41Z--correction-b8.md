窗口制的 judgment_gap 判定条件是「上一次捕获之后是否存在任何判断」，deliberate 取全时间轴，不受当前 witness 约束。

后果：任意一条与该变更无关的判断，只要时间晚于上一次捕获，就会让缺口从 boot 里消失。在临时副本上实测：追加一条无关 decision 前 boot 显示 2026-07-29T08-05-31Z--witness 未解释，追加后 Unexplained change 整节消失。

于是 AGENTS.md 写下的「同样的通知会出现在下一个 agent 的 boot 里，所以这个遗漏是被继承的，不是被遗忘的」是假的。遗忘的代价从「需要有人主动掩盖」降到了「正常工作一轮」。

更深一层：goal-b8 的 done_when 自己写的就是「其后没有任何 judgment 的 witness」。这个规格与它同一句里要的「跨会话继承」不相容——任何「变更之后有判断」形式的规则都会被下一次无关追加清偿。goal-b8 被 shell verifier 关闭（unittest + doctor 全绿），而测试里没有一条检查继承属性，验证器比 done_when 弱。这正是 goal-b8 正文自己描述的 (B) 类失败：测试全绿是因为测试编码了同一个错误信念。

修法不是收紧窗口边界。数据显示两个方向都错：judgment 有时写在 witness 之前（16:50:15 → 16:51:01），有时写在之后（19:15:07 → 19:15:35），而向量里没有 turn 边界可用——session_start 按 B2 归宿主。任何按邻近度的归因都必然在一侧犯错。

所以配对改为显式事实，两个方向各由知情的一侧写下：
- witness 在捕获时写 explained_by（只有运行时知道窗口；下界取闭区间，因为秒级时间戳下 commit 与其判断常落在同一秒）
- 事后补记的判断用 note.py --explains <witness-id>

两者都不存在时才是真遗漏，且不会被任何无关追加清偿。新增测试 test_unrelated_later_judgment_does_not_settle_it 就是 goal-b8 当初缺的那条检查。
