查 Kiro CLI 文档核实到：钩子只在 agent 配置 JSON（.kiro/agents/<name>.json）的 hooks 字段里生效，触发点是 agentSpawn / userPromptSubmit / preToolUse / postToolUse / stop，**没有 agentStop**。

Sula 的 hooks/install.py 一直写的是 .kiro/hooks/sula-witness.kiro.hook，格式为 when/then、触发点 agentStop——那是 Kiro IDE 的格式，Kiro CLI 从不读它。实测本项目 .kiro/agents/ 为空、无 workspace settings，所以这个钩子从未触发过。也就是说：非 git 底座的机械捕获从 v1.1 起一直没在工作，而 install.py 一直报告「kiro installed」。这是工具自己在说谎，比缺功能更糟。

本轮 4 个新接入项目全是非 git，全部只装了这个死钩子——它们的捕获实际为零。

两个可用事实：一、agentSpawn 钩子的 stdout 会被直接加进 agent 上下文，所以 boot 可以从「靠 agent 记得跑」变成机械注入。二、stop 在每轮回答结束时触发，是 witness 的正确挂点。

但不劫持默认 agent：自定义 agent 会丢掉 kiro_default 的系统提示词，那是用户没要求的降级。所以捕获的保证放在操作系统层——macOS 用 launchd（比 cron 可靠，cron 读 iCloud 路径需要 Full Disk Access），git 仓库继续用 post-commit；agent 配置写出来但不设为默认，由用户一条命令自选。
