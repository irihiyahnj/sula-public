「有变更无判断」可以三种方式执行，选第三种。

一、doctor exit 1。诱人但错：缺一个判断不是结构畸形，而且每个 goal 的 verifier 都含 doctor，于是任何有待记录判断的时刻都会让验证失败——包括改个 typo、跑一次 formatter。结果是把琐碎改动也逼出片段，即用 C7 换 E8，净亏。

二、pre-commit 拒绝提交。技术上可行，但四处都错：它与 substrate 搏斗（B7 说存储与并发归 substrate）、只在 git 上成立、--no-verify 一秒绕过、并且它阻塞的是用户自己的工作。Sula 从不自己调度或强制任何事。

三、永久可见。turn mark 当场对人说，boot 让下一个 agent 继承。这与 decision-trust-is-reader-side 是同一个形状：约定拦不住假话，它让假话永远留痕；同样，它拦不住判断缺席，它让缺席永远可见。append-only 系统里，永久可见就是最强的执行手段——比拒绝更强，因为拒绝可以绕过，而记录不能删。

关键不在提示语本身，在于它进了 boot。此前遗漏随会话蒸发：文件改了、原因没写、对话关闭、无人再知道缺了什么。现在遗漏被下一个 agent 读到，成为继承的债务。

判定口径：只有 evidence 是机器能写的格，所以 evidence 本身不能销缺口（verification-fact 也不行）；judgment 与 direction 都是深思后写下的，都能销。baseline witness 与无变更 witness 不计。
